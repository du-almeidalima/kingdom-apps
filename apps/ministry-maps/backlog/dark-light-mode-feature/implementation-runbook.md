# Dark/light mode implementation runbook

**Status: Ready for later execution**
**Scope: ordered instructions only; all tasks remain unchecked because production code is unchanged**

This is the execution authority for the feature. Read [requirements.md](./requirements.md), [technical-design.md](./technical-design.md), [assets/theme-token-contract.md](./assets/theme-token-contract.md), [style-migration-matrix.md](./style-migration-matrix.md), [assets/route-component-matrix.md](./assets/route-component-matrix.md), and [testing-and-documentation.md](./testing-and-documentation.md) before starting.

## Non-negotiable execution rules

- Execute phases and numbered tasks in order. Complete a task’s code, focused tests, matrix updates, and stop check before the next task.
- If implementation contradicts `requirements.md` or a current business state does not map to the token contract, stop and amend/approve the contract. Do not guess.
- Set only the actively implemented migration rows to `In progress`; set them to `Done` only with code, automated tests, rendered-color classification, explicit light/dark visual evidence, and passing focused gates.
- Run Nx through the root package toolchain. If narrowing a target, inspect `npx nx <target> <project> --help` or current target configuration first; do not guess flags. The full target remains the phase gate.
- Record baseline failures separately. Never delete, skip, loosen, or replace a failing test with a fake assertion.
- Keep every new/modified component standalone; use `inject()` for new dependencies; use kebab-case files; use `@kingdom-apps/common-ui` for cross-project TypeScript imports.
- Do not refactor feature-routing NgModules, route guards, data models, repositories, Firebase, unrelated constructor injection, directory typos, or general design-system APIs.
- Do not add Firestore/user persistence, a navigation toggle, extra preferences, global transitions, screenshot infrastructure, widespread `dark:` classes, or blanket image inversion.
