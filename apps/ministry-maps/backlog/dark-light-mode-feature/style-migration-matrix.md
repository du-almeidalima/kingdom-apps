# Style migration matrix

**Status: Seeded for implementation; every row is intentionally `Not started`**
**Scope: planning ledger; no listed production file has been migrated by this packet**

Read [requirements.md](./requirements.md), [technical-design.md](./technical-design.md), and [assets/theme-token-contract.md](./assets/theme-token-contract.md) before changing a row. Route roles, fixtures, and state coverage are expanded in [assets/route-component-matrix.md](./assets/route-component-matrix.md).

## How to use this matrix

Allowed status values are exactly `Not started`, `In progress`, `Blocked`, and `Done`.

For one row at a time:

1. Set the row to `In progress`.
2. Classify each rendered-color search match in the listed files as `migrate`, `retain with reason`, or `false positive`.
3. Replace presentation values with existing semantic tokens; amend the token contract first if no role fits.
4. Cover only states the component actually supports: default, hover, active, selected, `:focus-visible`, disabled, placeholder/autofill, validation, loading, and responsive/open-overlay states.
5. Update the adjacent test in the same slice when markup, classes, inputs/defaults, or behavior changes.
6. Run the focused test/lint gate and perform the explicit light/dark scenario in this row.
7. Mark `Done` only after code, focused tests, search classification, and visual evidence are all complete.

**Do not proceed to the next row while a focused command fails.** Do not use `color.scale(var(--token), ...)`, global search/replace, `dark:` proliferation, or palette names in new CSS variables.
